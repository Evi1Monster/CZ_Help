# 插件内全屏渲染验证记录

日期：2026-09-06。

实现文件：`plugin/render_hook.h`、`plugin/render_hook.cpp`、`plugin/iat_hook.h`。
测试文件：`plugin/render_tests.cpp`。

## 接入与生命周期

- `Install()` 在插件生命周期中查找已经加载的 `SDL2.dll`，按 PE 导入目录和导入名称验证 `GDI32.dll!SwapBuffers`，并要求当前导入地址等于系统导出地址。只修改当前进程中该指针槽，不写游戏磁盘文件，不使用私有偏移或远程注入。
- `Update(const Snapshot&)` 接收原有 v1 快照。交换缓冲之前，`BeforePresent(HDC)` 在当前游戏 OpenGL 上下文的默认后缓冲绘制。
- 导入槽写入使用临时页保护和原子比较交换；恢复时只替换仍由自己占有的槽。其他插件随后修改该槽时保留它，并保留恢复记录，以便所有权回到本插件后再次恢复。
- `Shutdown()` 停止后续绘制、恢复自己的导入槽、发布不可用状态并关闭通道。渲染侧以非阻塞 SRW 锁获取状态和快照，竞争时跳过帧。
- 安装回调前以 `GetModuleHandleExW(FROM_ADDRESS | PIN)` 固定本插件 DLL 到进程退出。IAT 恢复不能撤销其他线程已经读取的函数指针；固定模块保证晚到的回调仍可安全转发原始函数。更新 DLL 需要退出游戏后进行。

## 绘制条件与状态

- 读取 `Local\\CZHelp.Render.Control.v1.<pid>` 控制通道，500 ms 后失效；互斥锁暂时忙时沿用尚未过期的最近控制值。
- 完成读取后取得当前时间，避免并发发布的新时间戳被误判为未来值。
- 仅在控制有效且开启、快照有效且为本地活动会话、目标通过 `IsTarget`、游戏绘制窗口位于前台时绘制。
- 方框使用原界面橙色；HP 采用自带 5×7 位图字形，以实际生命比例从绿色渐变到红色，显示数值及 `HP`，没有血条。
- 每次有效的 OpenGL 交换独立于辅助功能开关发布状态 1 和客户区尺寸；上下文不可用时发布状态 2。因此用户关闭辅助功能后，外部窗口仍可判断内部呈现链是否工作。

## OpenGL 状态隔离

- 先检查属性栈、投影栈和模型视图栈是否有余量；空间不足时跳过绘制。
- 保存并恢复固定管线属性、模型视图矩阵、投影矩阵、矩阵模式、视口、活动纹理单元、当前 GLSL 程序，以及支持时的独立着色器管线。
- 支持默认后缓冲绘制及 FBO 状态恢复。核心 / ARB FBO 仅暂时切换 draw framebuffer，保持 read framebuffer；EXT FBO 使用其对应接口。
- 先恢复原 FBO，再恢复其 draw-buffer selector，避免将 `GL_COLOR_ATTACHMENT0` 错误应用到默认后缓冲。
- 绘制期间关闭纹理、深度、模板、剪裁、混合、光照、雾、逻辑操作及其他会影响二维方框的固定管线状态。按上下文能力处理多重采样、sRGB、独立着色器管线和 ARB 程序。
- 对缺少必要函数的上下文或不支持固定管线的 core profile 报告不可用。未建立自己的着色器、字体纹理或持久 OpenGL 对象，因此无跨上下文 GL 资源清理问题。

## 实际执行的验证

先创建真实 WGL 像素测试并配以空实现；测试以“后缓冲应有橙色方框”断言失败，确认能够检测原始缺失行为。实现后在以下环境完成 Debug 和 Release 验证：

- x86 MSVC 14.44 / Windows SDK 10.0.26100.0。
- NVIDIA GeForce GTX 1660 Ti，OpenGL 4.6.0 NVIDIA 610.88。
- 320×240 的真实双缓冲 Win32/WGL 窗口；通过 `glReadPixels` 检查结果。

通过的检查：

1. 开启控制时真实默认后缓冲出现预期投影区域的橙色方框；100 HP 的文字为绿色，1 HP 为红色。
2. 方框内部透明，旁边没有绿色血条。
3. 关闭控制、过期控制、过期快照、非本地会话、其他窗口位于前台，以及关闭渲染器后的晚到调用，均不产生方框。
4. 关闭辅助功能仍发布有效状态 1 和 320×240 尺寸。
5. 真实 GLSL 程序和可分离着色器管线、完整离屏 FBO、特殊视口、颜色掩码、投影 / 模型视图矩阵、活动纹理、深度 / 剪裁 / 纹理状态同时存在时，方框仍进入默认后缓冲；调用后逐项验证状态恢复，并检查 `GL_NO_ERROR`。
6. 修改测试程序真实 `GDI32!SwapBuffers` 导入槽，验证回调调用原函数、恢复后绕过回调、拒绝不匹配的原始函数、保留后续钩子，以及按所有权顺序恢复两层钩子。

最终运行命令：

```powershell
cmake --build build --config Debug --target render_tests --parallel 4
.\build\Debug\render_tests.exe
cmake --build build --config Release --target render_tests --parallel 4
.\build\Release\render_tests.exe
```

两种配置最终均返回退出码 0。编译和测试窗口在受控提升权限环境中执行；普通沙箱无法令测试窗口取得前台，不能用于前台门控的有效验证。

Release 测试发现并修正两项测试夹具优化问题：编译器跨多次调用缓存 IAT 地址，以及链接器合并行为相同的回调。测试使用独立的 `noinline` 导入调用入口，以及具有不同可观察副作用的第二层回调，保证每次调用重新进入真实导入槽，且两层钩子可分别验证。

## 集成要求与验证边界

- 渲染库需编译 `plugin/render_hook.cpp`，链接 `cz_core`、`opengl32`、`gdi32`、`user32`；测试编译 `plugin/render_tests.cpp` 并链接该渲染库。
- 本报告证明真实 WGL 后缓冲绘制、状态隔离和导入槽生命周期。没有操作实际游戏或安装插件，尚不能据此宣称在 Condition Zero 独占全屏模式中已经完成实机验证。
- 实际游戏运行时是否经过已经核实的 SDL2 交换路径，以及实际全屏视觉效果，需要由根任务完成游戏验证；这与 WGL 自动化验证分开记录。
