# 连跳与 KZ 功能设计草案

状态：已被用户取消。用户明确要求仅保留“按住空格自动跳”，以下内容只保留为历史草案。当前规格见 `2026-09-06-bhop-design.md`。

## 建议首版

| 功能 | 行为 |
| --- | --- |
| 自动连跳 | 开启后按住游戏跳跃键（默认空格），落地连续起跳，松开停止；使用正常跳跃物理 |
| 速度显示 | 实时水平速度，单位 u/s |
| 跳跃统计 | 一次有效起跳至落地的水平位移、起跳速度、空中最高速度；标明水平位移，不冒充竞赛 LJ 标准分数 |
| 存点 / 回点 | 保存当前地图中站立且落地的位置和朝向；回点前检查碰撞，回点后清零速度并取消本次跳跃统计 |
| 手动计时 | 开始、暂停、继续、重置；使用游戏时间，切图重置 |
| 独立开关 | 连跳与各训练显示可分别启用；F8 继续仅控制现有透视，F9 方框与 F11 变色 HP 数字保持原有用途 |

KZ 主开关建议 F3，存点 F4、回点 Shift+F4；计时操作先放在软件面板，可配置快捷键。已检查的游戏配置中 F3 和 F4 没有原始绑定。原有 F6、F7、PageUp、PageDown、End 已被游戏占用。

如用户选择操作辅助包，扩展为：自动空中加速（辅助 strafing 输入）、跳跃时自动蹲下、接近平台边缘时自动起跳。三项均独立开关，默认关闭；它们不等于速度显示或跳跃统计。该组必须根据用户的范围选择纳入最终规格。

## 实现路线

推荐扩展已安装的 C++ Metamod 插件，在 `PM_Move` 前处理本地玩家的移动输入，并在移动后采集统计；软件面板通过带版本和有效期的本机控制消息发送选项与存回点等操作，插件返回结果和训练数据。

备选方案是桌面模拟按键或游戏 cfg 脚本。它们较容易提供按键连发，但不能独立可靠判断游戏落地状态，也不适合作为存回点和准确统计的数据来源，因此本项目优先沿用插件。

## 状态与边界

- 延续单机范围：仅本地 listen server、`sv_lan=1`、唯一真人且本地玩家存活时启用。
- 连跳只处理地面步行移动，不干扰水中、梯子、旁观、死亡、冻结状态。
- 使用可写的 `playermove_t` 接口；不依赖修改 `CmdStart` 的 const 参数，也不引入游戏私有内存偏移。
- 关闭功能、软件失去游戏前台、控制心跳过期或关闭软件后，自动移动辅助停止。
- 存点只接受落地站立且空间有效的位置；回点空间被墙体、门或实体占用时拒绝并提示，不强行传送。
- 切图、断线或更换本地玩家后清除存点与计时；死亡取消当前跳跃统计。
- 控制消息包含进程和会话身份、有效期以及动作序号；存点、回点、计时操作不得因轮询重复执行。
- 升级共享协议时同步更新 EXE 和 DLL，对旧版本连接给出提示。更新 DLL 要在游戏退出后进行。

## 验证

先测试按住 / 松开 / 空中 / 落地 / 水中 / 梯子 / 禁用状态，统计落点与计时状态转换，以及存回点的有效空间判断。保留现有五组回归测试，构建 x86 Debug 与 Release。

然后在当前 Steam 版本实测连续跳跃、松开停止、转向、落地、蹲起及客户端预测。服务器侧行为正确不能直接证明画面没有预测纠正，未完成实机测试时须如实记录。

## 技术依据

- 项目使用的 Valve SDK `engine/eiface.h` 定义 `pfnPM_Move`，`pm_shared/pm_defs.h` 定义可写 `cmd` 与 `oldbuttons`。
- [Valve PM_Jump 与移动实现](https://github.com/ValveSoftware/halflife/blob/master/pm_shared/pm_shared.c)：跳跃由落地状态、当前按钮与旧按钮共同决定。
- [ReHLDS 服务端移动调用顺序](https://github.com/rehlds/ReHLDS/blob/master/rehlds/engine/sv_user.cpp)：用于对照公开实现的调用顺序，不能视为用户安装的 Steam 引擎源码。
