# CS 零点行动单机 BOT 辅助设计草案

状态：用户已于 2026-09-05 确认，按插件与透明窗口路线实现。

## 已确认的环境

- 用途：Steam《Counter-Strike: Condition Zero》普通本地 BOT 对战。
- 游戏路径：`D:\SteamLibrary\steamapps\common\Half-Life`。
- 本机 `hl.exe` 是 x86 / PE32；Condition Zero 的 Steam build ID 为 `12934630`。
- `czero/liblist.gam` 使用原始 `dlls\mp.dll`，未发现 `czero/addons`。
- 项目为尚无源文件的 Visual Studio C++ 工程，MSVC v143 已安装。
- 当前配置中 F8、F9、F11 未绑定；F1、F2、F5、F6、F7、F10 和 Insert 已有绑定。

## 功能与操作

| 操作 | 默认快捷键 | 行为 |
| --- | --- | --- |
| 总开关 | F8 | 暂停或恢复所有标记，保留两个独立选项 |
| 方框开关 | F9 | 独立切换敌方 BOT 的二维方框 |
| 血量开关 | F11 | 独立切换 HP 数字，不依赖方框开关；颜色按血量比例由绿渐变到红，不显示条状血量 |

配置文件允许修改快捷键并保存功能选项。启动时总开关关闭，方框和血量选项默认开启。按键按下沿触发一次，持续按住不会反复切换；仅在游戏处于前台时响应。

默认只标记存活的敌方 BOT。死亡、离开地图、退出游戏或数据失效时清除对应标记。隐藏标记不影响游戏鼠标输入。

## 实现路线比较

1. **建议：本地服务端插件 + 独立透明窗口。** 通过 Metamod 加载 x86 C++ 插件，读取本机对局的实体位置和真实血量，向桌面程序提供数据。避免依赖游戏私有内存地址，但需要安装插件，并使用窗口化或无边框窗口模式。
2. **外部程序直接读取游戏内存。** 启动形式更接近单独 EXE，但需要针对当前引擎确认实体、服务端血量和摄像机的地址与布局；游戏更新可能需要重新适配。不能用客户端结构中存在 `health` 字段来证明它包含所有 BOT 的实时血量。

不在未经验证的偏移地址上开发，也不将模拟数据演示当作游戏连接成功。

## 推荐路线的组成

- **`CZ_Help.exe`：** Win32 控制与透明覆盖窗口、快捷键、配置持久化、世界坐标投影和方框/变色 HP 数字绘制。覆盖区域跟随游戏客户区，处理移动、缩放、DPI 和最小化。
- **`cz_help_mm.dll`：** x86 Metamod 插件。通过 GoldSrc 服务端接口采集本地玩家和 BOT 状态；供本机普通 BOT 对局使用。
- **本机共享数据：** 使用明确版本、大小、进程身份、时间戳和同步规则的快照传输坐标、包围盒、血量、队伍与观察参数。读取端拒绝不完整或过期数据。
- **安装与恢复：** 提供脚本和中文说明；对需要修改的游戏配置先备份，恢复时只处理本工具的变更。所有构建产物先生成在项目中。

数据流程：本机对局实体 → 插件快照 → 坐标投影 → 透明窗口绘制。

## 兼容性验证顺序

第一阶段先在当前 Steam 版本验证插件加载、BOT 血量更新和摄像机投影，再完成覆盖窗口与设置。服务端观察角度与客户端最终画面可能因预测、视角晃动或开镜而不同，因此投影精度必须实测，不先承诺完全重合。

第一版支持窗口化和无边框窗口模式。独占全屏需要不同的呈现方式，不作为该路线的支持模式。

读取不到数据时显示连接状态并停止绘制；切图、重连、游戏退出后不得显示旧方框。不能准确确定本地玩家、队伍或视角时暂不绘制对应标记。

## 验收

- 在墙后仍可看到存活敌方 BOT 的方框，移动、蹲下和开镜时位置保持合理对齐。
- BOT 受伤后 HP 与服务端实际值一致；死亡后移除标记。
- 方框与血量可分别开启，总开关恢复时保留原来的组合。
- 快捷键长按只切换一次，切换至其他应用后不触发。
- 切图、最小化、退出及数据中断时无残留覆盖。
- 验证投影边界、配置错误与过期快照处理；执行 x86 Debug/Release 构建。
- 实际游戏验证结果与尚未验证的部分分别记录。
